IA32处理器体系结构

Intel x86 处理器：

复杂指令集计算机（Complex instruction set computer,CISC）
  1. 指令多、指令格式多（Linux程序设计只用到其中很少的子集）
  2. 性能难与精简指令计算机相比，在速度方面Inter做到了与RISC相当的性能，但功耗不低。

​ 8086是第一个16位intel处理器，主要用于IBM PC & DOS

概念

  1. 架构 指令集体系结构，处理器设计的一部分，理解或编写汇编/机器代码时需要知道。例如：指令集规范、寄存器
  2. 微架构：架构的具体实现，例如：缓存大小、核心的频率
  3. 代码格式：
    1. 机器码：处理器能直接执行的字节级4程序
    2. 汇编码：机器码的文本表示

IA32寄存器

  1. 基本寄存器： 寄存器是CPU内部的高速储存单元，访问速度比常规内存快得。包括：

    1. 8个32位通用寄存器（32个字节）
    2. 6个16位段寄存器（12个字节）
    3. 一个存放处理器标志的寄存器（EFLAGS）
    4. 一个指令指针寄存器（EIP）

  2. 系统寄存器：仅允许运行在最高特权级的程序（例如：操作系统的内核）访问的寄存器，任何应用程序禁止访问。

  3. 浮点单元

  4. 通用寄存器：AH,AL：8位+8位，AX：16位；EAX：32位

    1. EAX：用于存储运算结果（加法、乘法等）
    2. EBX：用于存储数据或地址
    3. ECX：用于循环计数、偏移量等
    4. EDX：用于存储运算结果（乘法、除法等）
    5. ESI、EDI：用于存储源地址和目标地址，常用于字符串操作
    6. ESP：栈指针
    7. EBP：基指针

  5. 段寄存器

    1. 在实地址模式下，段寄存器主要用于存放段的基址；段寄存器包括：CS、SS、DS、ES、FS、GS

    2. 段寄存器 (Segment Registers) 是用于存储内存地址段起始位置的特殊寄存器，通常用于分段寻址（Segmented Addressing）。在分段寻址模型中，内存被划分为不同的段，每个段都有一个起始地址，段寄存器用于存储这些段的基地址，以便CPU能够通过它们来访问内存中的不同部分。

      在x86架构中，段寄存器是为了实现分段内存管理而设计的，尤其是在32位和16位的x86处理器中。分段内存模型将内存划分为不同的段，每个段存储不同类型的数据或程序代码。段寄存器帮助计算内存地址，并指定程序可以访问的内存区域。

      x86架构中常见的段寄存器有以下几种：

      1. CS（Code Segment） - 代码段寄存器：

        功能：存储当前执行的代码段的基地址。CPU在执行程序时，指令的地址是通过代码段寄存器和指令指针（IP）组合来计算的。CS寄存器的值指向存储代码的内存区域。

        使用场景：执行指令时，CPU会通过CS寄存器定位代码段的起始地址，然后结合IP（指令指针）来获取具体指令的地址。

      2. DS（Data Segment） - 数据段寄存器：

        功能：存储程序数据部分的基地址，通常用于存储程序中的常规数据（如全局变量、局部变量、静态变量等）。

        使用场景：数据段通常包含了程序运行期间需要使用的数据，CPU可以通过DS寄存器来访问数据段的内存。

      3. SS（Stack Segment） - 堆栈段寄存器：

        功能：存储栈的基地址，栈是程序执行过程中用于存储局部变量、函数返回地址、保存寄存器等内容的内存区域。SS寄存器指向栈的起始地址。

        使用场景：当程序执行函数调用或处理局部变量时，栈寄存器SS用于定位栈内存。

      4. ES（Extra Segment） - 额外段寄存器：

        功能：用于某些特定的内存操作，如字符串处理。它提供额外的数据段，通常与字符串操作相关联。

        使用场景：在进行字符串复制或处理时（如MOVSB``MOVSW等指令），ES寄存器作为目标段寄存器。

      5. FS和GS - 扩展段寄存器（仅限于某些架构）：

        功能：在一些现代的x86架构中，FS和GS提供额外的段寄存器，它们通常用于特定的任务或操作系统级别的任务，如访问线程局部存储（TLS）等。

        使用场景：这些寄存器通常用于访问特定的内存区域，如线程栈、局部存储等。

      6. 段寄存器的运作方式：

      段寄存器存储的是一个段的基地址，结合偏移量（即指令指针或栈指针等）后，形成一个完整的内存地址。在16位模式下，内存地址是通过将段寄存器的值左移4位，然后与偏移量相加来计算的。这个机制确保了程序可以访问到不同的内存段。

      例如：

      • 物理地址 = 段寄存器值 << 4 + 偏移量
      • 如果CS = 0x2000，IP = 0x1000，那么物理地址 = 0x20000 + 0x1000 = 0x21000。

  6. 指令指针寄存器EIP

    也称为：程序计数器（Program counter ,PC）

    EIP始终存放下一条要被CPU执行的指令的地址

    有些机器指令可以修改EIP，使程序分支转移到新的地址执行，例如：JMP,RST

  7. EFLAGS寄存器（标志寄存器、条件码寄存器）

    1. EFLAGS又控制CPU的操作或反映CPU某些运算结果的二进制位构成

    2. 处理器标志包括两种类型：状态标志和控制标志

      进位标志CF：在无符号算术运算的结果中，无法容纳进位时被设置。

      溢出标志OF：在有符号算术运算的结果位数太多，而无法容纳于目标操作数时被设置。

      符号标志SF：算术或逻辑运算产生的结果为负时被设置。

      零标志ZF：在算术或逻辑运算产生的结果为零时设置。

      调整标志AF（Adjust Flag）：也称为辅助进位标志，8位操作数的位3到位4产生进位时被设置，BCD（二进制码十进制）算术运算需要使用。

      奇偶标志PF：结果的最低8位中，位1的总位数为偶数时设置该标志；否则清除该标志。

IA32的内存管理

  1. 实地址模式

    1. 处理器使用20位的地址总线可以访问1MB（0~FFFFF）内存

    2. 8086的模式，只有16位的地址线，不能直接表示20位的地址，采用内存分段的解决方法。

    3. 段：将内存空间划分为64KB的段Segment;

    4. 物理地址 = 段寄存器值 << 4 + 偏移量

      段寄存器：16位，存储段的起始地址。通过段寄存器，8086可以访问更大的内存空间。

      偏移量：16位，指定某个段内的具体地址。

程序是如何运行的

程序运行过程描述了从程序启动到程序退出的整个生命周期，涉及到操作系统和硬件的交互。以下是程序在计算机系统中的执行流程，特别是在8086架构中，程序的执行过程涉及从加载程序、初始化、指令执行、到程序退出的各个环节。

程序运行的过程可以分为以下几个阶段：

1. 程序加载（Loading）

在现代操作系统中，当程序启动时，操作系统将程序从磁盘加载到内存中。程序的代码和数据段被加载到内存的适当位置。操作系统会为程序分配所需的内存空间，并将其指令、数据和栈等加载到内存中。

在8086中：

  • 程序通常被存储在磁盘或其他外部存储设备上，当程序被执行时，操作系统会将程序从存储设备加载到内存中。
  • 由于8086采用 内存分段，程序的代码段、数据段和堆栈段将被分配到不同的内存段。

2. 初始化（Initialization）

程序启动时，操作系统需要进行一些初始化工作，确保程序能够正确运行。包括：

  • 设置堆栈：在程序运行时，堆栈用于存储函数调用的返回地址、局部变量和中断处理等信息。
  • 段寄存器初始化：操作系统会初始化段寄存器（如CS、DS、SS等），以确保程序能够正确访问其代码、数据和堆栈段。
  • 栈指针和指令指针初始化：栈指针（SS:SP）和指令指针（CS:IP）会初始化为程序的入口点，指向程序的开始部分。

3. 程序执行（Execution）

一旦程序被加载并初始化，CPU开始按顺序执行程序中的指令。程序的执行过程如下：

3.1 指令获取（Fetch）

CPU通过 指令指针（IP） 从内存中获取指令。指令指针存储的是下一条要执行指令的内存地址。8086架构使用分段寻址，指令指针和段寄存器组合来获取下一条指令的物理地址。

  • 例如，指令指针（IP）指向某条指令，段寄存器（如CS）指向程序的代码段。通过段寄存器和偏移量的组合，CPU能够获取到程序代码的物理地址。

3.2 指令解码（Decode）

获取到指令后，CPU将其解码，确定该指令的操作类型（如加法、跳转等），以及操作数的地址。CPU根据指令格式来解析操作码（Opcode）和操作数。

3.3 执行（Execute）

在指令解码后，CPU执行指令。根据指令的类型，可能会进行算术运算、逻辑运算、数据传送或控制操作。

  • 例如，如果是加法指令，CPU将执行相应的算术运算；如果是跳转指令，CPU会根据条件跳转到程序的其他位置。

3.4 更新EFLAGS寄存器

在指令执行过程中，EFLAGS寄存器会根据结果更新。例如，零标志（ZF）会在结果为零时被设置，进位标志（CF）在加法产生进位时会被设置。

4. 函数调用（Function Call）

在程序中，函数调用是常见的操作。当程序遇到函数调用时，以下过程会发生：

  • 将返回地址压入堆栈：程序将返回地址（即函数调用后应该继续执行的地址）压入堆栈中。
  • 更新堆栈指针（SP）：栈指针会根据栈操作（如压入返回地址和局部变量）进行相应的更新。
  • 跳转到函数入口：CPU根据函数的入口地址跳转到函数代码，开始执行函数体中的指令。

5. 中断和异常处理（Interrupts and Exceptions）

在程序运行过程中，可能会发生外部事件或错误情况，这时操作系统会介入处理，通常通过中断（Interrupt）和异常（Exception）机制：

  • 外部中断：例如硬件中断，CPU暂停当前程序的执行，跳转到中断处理程序（ISR）执行。常见的外部中断有定时器中断、输入输出设备的中断等。
  • 软件中断：程序中可能主动触发中断（如系统调用），操作系统会通过中断服务例程（ISR）来响应。
  • 异常：例如除零错误、访问非法内存等，程序会引发异常，操作系统处理异常后可能会终止程序或进行修复。

6. 程序结束（Termination）

当程序的所有指令执行完成后，程序会结束。此时，操作系统会释放为程序分配的内存，并将控制权交还给操作系统。

  • 返回值传递：如果程序有返回值（如函数的返回值），操作系统会将其传递给调用程序或操作系统的其他部分。
  • 栈的清理：程序执行完毕后，操作系统会清理堆栈中的数据，并释放与程序相关的资源。
  • 退出程序：操作系统将从程序的最后一个指令处继续执行，程序结束。

7. 8086中的栈和堆栈帧

在8086架构中，堆栈用于存储函数调用时的返回地址和局部变量。堆栈基于 SS:SP（堆栈段寄存器和堆栈指针）的组合来进行管理。

  • 当函数被调用时，返回地址会被推入堆栈，栈指针（SP）向下移动。
  • 当函数返回时，栈指针（SP）会弹出返回地址，程序跳回到调用点继续执行。

汇编语言

汇编语言（Assembly Language）是接近计算机硬件的一种低级编程语言，它直接与机器语言对应，但比机器语言更易于理解和使用。汇编语言是用特定的助记符（mnemonics）来表示机器指令，方便程序员进行编程。每种计算机体系结构通常都有自己的汇编语言（如x86汇编、ARM汇编等）。

汇编语言的特点

  1. 低级语言：汇编语言与机器语言非常接近，通常与处理器的指令集直接对应。与高级语言（如C、Python等）相比，汇编语言更加依赖硬件平台。
  2. 与硬件紧密结合：汇编语言直接操作硬件资源（如寄存器、内存等），可以精确控制程序的执行过程。
  3. 可执行效率高：由于它与机器代码非常接近，程序执行效率高，适用于对性能要求极高的系统（如嵌入式系统、操作系统内核、驱动程序等）。
  4. 助记符和操作符：汇编语言使用助记符来表示机器指令的操作码（Opcode），如 MOV（移动数据）、ADD（加法运算）、JMP（跳转）等。

汇编语言与机器语言的关系

  • 机器语言：机器语言是计算机能够直接理解的语言，采用二进制代码（0和1）表示每条指令。每种计算机处理器的指令集（ISA）都有自己特定的机器语言格式。

  • 汇编语言

    ：汇编语言通过

    助记符

    来表示机器语言的指令。例如，

    MOV

    指令可能对应着机器语言中的某个特定二进制代码。汇编程序通过汇编器（Assembler）将汇编代码翻译成机器代码。

    • 例如：MOV AX, 1（汇编语言）可能会被转换为机器语言指令 10111000 00000001。

汇编语言的基本组成

  1. 助记符（Mnemonics）： 汇编语言的指令通常以助记符表示，这些助记符为程序员提供了比机器码更易于理解的方式。例如：

    • MOV：将数据从一个位置移动到另一个位置。
    • ADD：将两个操作数相加。
    • SUB：执行减法。
    • JMP：无条件跳转。

  2. 寄存器（Registers）： 汇编语言可以操作处理器的寄存器。寄存器是CPU内部的高速存储单元，通常用于存储临时数据、操作数和计算结果。

    • 例如，x86架构中常见的寄存器有 AX、BX、CX、DX 等。

  3. 操作数（Operands）： 操作数是指令中的数据，可能是常量、寄存器、内存地址等。例如：

    • MOV AX, 5：将数值5存入寄存器AX。
    • ADD AX, BX：将寄存器BX的内容加到AX中。

  4. 标签（Labels）： 标签用于标记程序中的位置，通常在跳转指令（如JMP）中使用，表示跳转的目标位置。例如：

    LOOP_START:
    ; some code
    JMP LOOP_START ; 跳转回LOOP_START

  5. 伪指令（Pseudo Instructions）： 伪指令是汇编语言中的一些非机器指令，用于辅助程序的编写，如数据定义、内存分配等。例如：

    • DB：定义字节（定义数据常量）。
    • DW：定义字（定义数据常量）。
    • EQU：常量赋值。

汇编语言的常见指令

汇编语言的指令集取决于所使用的处理器架构（如x86、ARM等）。以 x86 架构为例，常见的汇编指令包括：

  1. 数据传送指令：
    • MOV destination, source：将源操作数的数据传送到目标操作数。
    • 例子：MOV AX, 5 将数值5存入AX寄存器。
  2. 算术运算指令：
    • ADD destination, source：将源操作数与目标操作数相加。
    • SUB destination, source：从目标操作数中减去源操作数。
    • 例子：ADD AX, BX 将BX的值加到AX寄存器中。
  3. 逻辑运算指令：
    • AND destination, source：执行按位与运算。
    • OR destination, source：执行按位或运算。
    • XOR destination, source：执行按位异或运算。
    • NOT destination：按位取反。
  4. 跳转指令：
    • JMP label：无条件跳转到指定标签处。
    • JE label：如果相等则跳转。
    • JNE label：如果不相等则跳转。
    • 例子：JMP LOOP 无条件跳转到LOOP。
  5. 比较指令：
    • CMP operand1, operand2：比较两个操作数，并设置条件标志。
    • TEST operand1, operand2：测试两个操作数的按位与结果。
  6. 中断指令：
    • INT：触发中断。通过中断机制，可以从程序执行中断并转向一个中断处理程序。

示例：x86汇编语言程序

下面是一个简单的x86汇编语言示例，展示了如何将两个数相加：

section .data
    num1 db 5           ; 定义数据常量 num1 = 5
    num2 db 10          ; 定义数据常量 num2 = 10

section .text
    global _start       ; 告诉链接器程序入口点

_start:
    MOV AL, [num1]      ; 将num1的值加载到AL寄存器
    ADD AL, [num2]      ; 将num2的值加到AL寄存器
    ; 结果存在AL寄存器中，AL = 15
    
    ; 程序退出
    MOV eax, 1          ; 系统调用号 1，表示退出
    int 0x80            ; 调用Linux系统调用
